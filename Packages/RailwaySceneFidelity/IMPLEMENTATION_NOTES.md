# 実装メモと制約

## シーン配置

ルートはチェーン数昇順の `SceneRouteControlPoint` 列で表し、区間ごとにcubic Hermite補間します。明示接線を使う場合、制御点位置の変化と同じメートル基準で `d(position)/d(chainage)` を渡します。接線がない箇所では隣接点間の割線から接線を得ます。位置・接線は実測線形の代わりにはならず、入力品質がそのまま描画位置へ伝わります。

各地点の forward/right/up をその地点の接線から構成し、任意のバンク角を適用します。線路・枕木・バラスト・架線・ホーム・街路の局所要素はチェーン数上で再サンプルして位置と向きを求めます。急曲線や位置サンプル間隔が粗い経路は、制御点を増やして実機で滑らかさを確認してください。

## 形状・メッシュ

軌道部材はレール・枕木・締結装置・バラスト・路盤に分離し、短い曲線追従セグメントにします。架線は接触線・吊架線を短い接線区間に分け、スパン内にごく小さい下垂を幾何で付けます。沿線の建物・車両・人物・植生は、同一の決定論的seedから組み立てる独自形状で、反復して同じシーンを生成できます。

RealityKit adapterは箱・円柱・楕円球をローカル頂点へ展開し、アセンブリー内の材質ごとに `MeshDescriptor` を作ります。詳細プリミティブを個別ModelEntityとして大量に追加せず、材料別に一括化します。UV/テクスチャは持たず、SimpleMaterialの色・粗さ・金属度のプレースホルダーパレットです。

## 品質と密度

`performance / balanced / highDetail` は、可視距離、レール小片の長さ、沿線要素間隔、景観アセンブリー予算、詳細段階を調整します。線路・枕木・架線位置を画質プリセットに合わせて間引いたり、枕木間隔や実寸を変えたりはしません。景観予算を使い切っても軌道・架線の必須部材は残ります。

LOD境界、視野カリングと可視距離、セグメント長、scene budgetは設計初期値です。描画負荷・CPU/GPU時間・メモリー・電池・熱は測定していません。生成メッシュと描画コストは、入力距離、プラットフォーム数、detail level、道路/駅の範囲でも変わります。実機でprofileを調整し、視距離や走行速度が変わるときのLOD切替・ポッピングを確認してください。

## 未実施・禁止される誤解

- 生成された外観は、著作権上の第三者メッシュを複製しない独自の手続き形状です。ただし簡略プリミティブで、手作業のフォトリアルアセット、写真測量、実在の素材調査と同等ではありません。
- 既定の軌間・枕木間隔・電化高・ホーム位置・建物間隔は初期値または利用者入力値です。鉄道構造物の設計基準、保安、安全クリアランス、建築基準への適合を保証しません。
- サンドボックスにSwift、Xcode、iOS SDKがありません。`swift test`、Swift型検査、RealityKit APIのコンパイル、実機画面、iPhone性能・熱・電池計測は実施していません。
- 湿潤・積雪は単色の色と roughness ヒントです。新しい草法面は積雪ヒントの対象、水面は対象外です。積雪メッシュや摩擦の追加はありません。
- 高品質ホストは既にこのビルダーを呼びます。低/中品質ホストは `SceneCorridorLandmarkSchedule` だけを共有し、粗い箱を別に置きます。踏切は静的 `PLACEHOLDER` で、保安装置や固定tick物理には接続していません。iOS描画と負荷は未測定です。
