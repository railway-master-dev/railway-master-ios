# Synthetic railway 3D asset library

The owner described the earlier base GLBs and the newly supplied add-on GLB pack as generated with ChatGPT. This is owner-provided provenance, not an independent authorship or legal-rights determination. The project inspected the bundled files structurally, but does not claim an exclusive license or provide a legal opinion. No third-party model, operator logo, commercial livery, proprietary sound, external image, or external GLB resource URI is included. Review source terms before commercial distribution.

## Models and topology

- Generic commuter-car exterior and driver-cab interior, plus selected detailed owner-provided commuter-car and cab GLBs
- A 20 m track panel, railway equipment module, and suburban corridor modules
- Side-platform, island-platform, three-track passing, four-track major, terminal, and original five-track/four-platform hub station modules
- `station_layouts_32.json`: 28 mainline and 4 branch stations, with platform counts and archetypes mapped to model assets

Only the detailed commuter car and cab interior were selected from the add-on pack. The supplied pack contained 27 GLBs and 21 PNGs; duplicate base GLBs were not copied, the other 15 distinct high-fidelity GLBs and all PNGs were not bundled. The selected detailed assets use Z-up coordinates, local +X along the car, and metre-scale bounds. At runtime, a -90° X-axis conversion maps Z-up to the app’s Y-up frame; `COLOR_0` is mapped to per-primitive RealityKit materials. Every selected primitive has a uniform per-vertex color, so this conversion retains its authored color without flattening a gradient.

The five-track/four-platform station is original project geometry generated by `Scripts/generate_4platform_station_glb.py`. It uses the same Y-up, +X-longitudinal convention as the base station modules.

## Runtime integration

The app contains a native GLB-to-RealityKit mesh loader. The selected detailed car and cab are used for the high-fidelity lead car; the nearest station model is streamed from the active route's canonical stop chainage; track, equipment, and corridor modules are placed on the seeded route. Existing procedural vehicle geometry remains a fallback if an asset cannot load. The GLBs are retained as editable source assets.

## Important limits

All railway, station and route data are synthetic placeholders, not survey, engineering, operational, or safety data. Review imported models on iOS hardware for visual scale, transparency, draw-call and frame-rate behavior before release. No iOS/Xcode build or device render is claimed by this handoff.
