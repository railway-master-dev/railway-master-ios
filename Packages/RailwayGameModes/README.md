# RailwayGameModes

仕様書1・2にある9つのゲームモードを、iOSアプリへ組み込めるSwift Packageとして定義したworkstreamです。SwiftUI画面や物理演算は持たず、ホスト側のシミュレーション値を受け取る状態機械、モード別操作、成否・終了評価、UI用状態を提供します。

> **PLACEHOLDER — 架空ゲームデータのみ。** 同梱の駅・列車・時刻・イベント・景観・放送ID・閾値は試遊用の架空値です。実在の鉄道路線、車両、運転取扱、資格訓練、安全手順を表すものではありません。実務・実設備には使用できません。

## 9モードの契約

| モード | 初期状態・目的 | 操作／成功・失敗 | UI表示・終了評価 |
|---|---|---|---|
| 運転士 | ホスト列車状態と架空乗務チェック先頭から開始。チェック順、停車順、速度条件を守る。 | 順序付き乗務チェック、停止・閉扉状態での出発確認、駅・終着記録。全チェック、出発確認、必須駅、終端停止で成功。速度超過、走行中のドア開、順序違反で失敗。 | 位置・速度・上限・停車進捗・次チェック・出発確認。チェック率、停車達成、速度超過、最大加速度／ジャーク。 |
| ダイヤ | 架空の秒単位到着／発車計画とゲーム内回復枠から開始。 | 駅到着／発車を記録し計画差を算出、必要なら駅単位の回復判断。全時刻点観測、順序・終端達成、許容差内または回復判断で成功。時刻点不足、許容差超過、駅順違反で失敗。 | 次駅、到着／発車の計画差、遅延、回復枠。定時イベント数、最大絶対差、訪問駅、順序違反、回復数。 |
| フリー | ホストから実際に受け取った路線・車両・天候・時間・季節・乗車率だけを引き継ぎ、未接続値は未設定。 | 目標／地点の記録と路線・車両・天候・時間・季節・乗車率の変更要求。任意終了で自己設定プレイとして完了し、合否点は付けない。 | 現在値と要求値、自己目標、地点、経過時間。走行時間・地点数・変更要求数。 |
| 車掌 | ホストの明示されたドア状態と未確認駅一覧から開始。 | 停車中にホーム側を選んでゲーム内ドアを操作し、ホストの閉扉状態を受け取って確認。各駅の確認と駅名／必須車内案内で成功。ホーム側違い、走行中のドア開、未確認のまま進行で失敗。必要なドア・駅名入力がなければ判定不能。 | 駅・ホーム側・ドア状態・確認済み駅・案内キュー・手順エラー。確認駅数、案内数、エラー数。 |
| 異常対応 | 架空イベントの設定条件が満たされるまで待機。 | 期限付きイベントカードでゲーム専用の選択肢を選ぶ。想定選択肢を期限内に選べば成功。誤選択・期限切れ・未解決終了で失敗。 | イベント種類／状態・残り秒・選択肢・ヒント数・注意表示。応答結果・時間・ヒント数。 |
| 教習 | 操作、信号表示、保安装置UIなど、架空教材の順番付きステップから開始。 | 停止・速度上限・駅状態・ホスト表示のいずれかを満たして教材を順に完了。全ステップを誤り上限未満で終えれば成功。誤答3回で失敗。 | 現ステップ・前提条件・表示プロンプト・完了数・誤り数・ヒント数。完了率、誤り、ヒント。 |
| 全線 | 始発位置と架空路線全長・順序付き停車駅から開始。始発位置でない場合は失敗ではなく判定不能。 | 停車駅順と終端までの進捗を記録。必須駅を順に通過し、終端で停止して成功。終端時の未通過駅、順序違反、別路線入力で失敗。 | 全線進捗・次駅・通過駅・終端・区間位置。進捗、達成駅、順序違反。 |
| 観光 | 架空の景観一覧と未発見状態から開始。 | 景観IDがホスト表示中で、位置範囲・上限速度内にあるとき観察を記録。必要数（最大2件）で成功。終端までに不足すれば失敗。 | 表示景観・観察条件・発見数・路線進捗。観察数、発見率、終端進捗。 |
| 会社運行 | 複数の架空列車・タスク・時間枠を未割当で読み込む。タスク対象列車のホスト状態がなければ判定不能。 | 列車タスクを許可時間枠へ割当し、期限と線路上の近接競合を確認。全件を期限内に重複なく割り当てれば成功。同一枠競合、期限切れ、未割当終了で失敗。 | 列車・未割当タスク・時間枠／線路・競合・期限超過。割当数、競合数、期限超過。 |

仕様書2の「練習／本番／トラブル対応／フリーラン」は9モードとは別の `GameModePlayStyle` として保持します。

## iOS統合

`Package.swift` のライブラリプロダクト名は `RailwayGameModes`、deployment targetはiOS 17です。このプロジェクトではすでにapp targetへリンクされ、`GameModeSessionSheet`と`SimulatorModel`から利用されています。データ境界とadapter契約は [`INTEGRATION.md`](INTEGRATION.md) を参照してください。

主な公開APIは `GameModeSimulationSnapshot`（ゲーム用に整形したホスト値）、`GameModeSimulationSource`（読み取り境界）、`GameModeScenario`（データ注入）、`GameModeSession`（決定的状態機械）、`GameModeAction`（ユーザー操作）、`GameModeHostEffect`（ホストへ返す要求）、`GameModeCatalog`（静的UI契約）です。UIは `session.status`・`session.progress`・`session.definition`・`session.evaluation` から描画できます。ホストが後続スナップショットを返さない要求は、成功した現在値として扱いません。
