# 仕様書との対応メモ

## 参照した入力

- **ユーザー提供の仕様書1** — 必須モードの概要（70–79行）、運転士業務（889–913行）、異常時シナリオ（966–987行）、9モード一覧（989–1001行）、評価項目（1003–1020行）。
- **ユーザー提供の仕様書2** — ゲームのプレイ種別（105–108行）に「練習／本番／トラブル対応／フリーラン」と記載。
- **ユーザー提供の路線データ要求** — データ状態、出典、未確認値の扱いを含む。要求外の路線・実データを新規に取り込まない。

仕様書1の列挙する9モードは、運転士、ダイヤ、フリー、車掌、異常時、教習、全線、観光、鉄道会社運行。仕様書2の4種別は同じ一覧の代替ではなく、モードに重ねるプレイスタイルとして扱う。未接続データを推測して実装済みと表示しない。

## 実装境界

- このパッケージはモードごとの値型契約、状態遷移、テスト可能な成否・終了評価だけを提供する。SwiftUI、物理演算、音声、路線読込、永続化は所有しない。
- 全同梱シナリオ、駅・列車・時刻・閾値・イベント・ランドマーク・放送IDは架空の `PLACEHOLDER` ゲーム値。実在路線・車両・鉄道規程・運転取扱を示さず、実務・資格・安全訓練には使用しない。
- ホストが提供しない値は `nil` / `.unknown` のままとし、成功・失敗に推測で変換しない。ホストは各 `GameModeHostEffect` を検証して適用し、後続の `GameModeSimulationSnapshot` で状態を返す。
- 仕様書1の運転士業務は出勤・点呼・乗務準備・車両確認・運転台起動・出庫・出発前確認・指差喚呼・戸閉確認・発車・信号確認・駅進入/停車・停車後確認・異常時対応・終着・入庫・終了を列挙する。モジュールでは架空の順序付き教材チェックとして扱い、実手順や実設備を定義しない。
- 仕様書1はフリー運転の車両・路線・天候・時間選択、車掌のドア・車内放送・駅名案内、異常イベント例（車両故障・急病人・踏切支障等）、教習（操作・信号・保安装置）、全線（始発から終着）、観光（車窓）、会社運行（複数列車ダイヤ管理）を概要要件として列挙する。未接続の各入力はホストから注入されるまで表示・評価しない。
- 仕様書2の練習／本番／トラブル対応／フリーランは `GameModePlayStyle` として9モードから分離し、二重に9モード数へ加えない。
